General

Conceptos generales

Formato de respuesta

Todas las respuestas siguen la misma estructura:

// Éxito { "success": true, "data": { ... } } { "success": true, "data": [ ... ], "mensaje": "..." } // Error { "success": false, "error": "Descripción del error" }

Fechas de Firestore

Las fechas almacenadas como Timestamp en Firestore llegan serializadas en las respuestas REST como:

{ "_seconds": 1714000000, "_nanoseconds": 0 } // Para convertir a Date en JS: const date = new Date(ts._seconds * 1000);

Archivos estáticos

Las imágenes subidas (fotos de perfil, fotos finales de proyectos, fotos de solicitudes) se sirven en:

http://<host>:5000/uploads/<nombre-archivo>

CORS y Content-Type

ℹ️
CORS está abierto (*). Los endpoints que aceptan JSON requieren el header Content-Type: application/json. Los endpoints de subida de imágenes usan multipart/form-data — no agregar Content-Type manualmente, el navegador lo gestiona solo.
Auth

Autenticación — /api/auth

MétodoRutaBody (JSON)Descripción
POST /register { nombre, email, password, rol, telefono? } Registra usuario. rol: "empleador" o "empleado". Envía código de 6 dígitos al correo (expira en 15 min).
POST /verificar-codigo { email, codigo } Activa la cuenta con el código recibido por correo.
POST /login { email, password } Devuelve { uid, email, token }. Solo cuentas verificadas. Error 403 si no está verificada.
POST /recuperar-password { email } Envía enlace de restablecimiento de contraseña al correo.
POST /diagnostico { uid, habilidades: string[] } Guarda las habilidades del empleado. Llamar una vez luego del registro, antes de la primera sesión.
⚠️
El token devuelto por /login es un Firebase ID Token válido por 1 hora. Actualmente el backend no valida este token en ningún middleware — está disponible para futuras implementaciones de seguridad.
Usuarios

Usuarios — /api/usuarios

MétodoRutaBody / FormaDescripción
GET /:id — Perfil completo del usuario. Devuelve todos los campos del documento en Firestore.
PUT /:id { nombre?, telefono?, habilidades? } Edita perfil. Solo los campos enviados se actualizan (parcial).

Solicitudes

Solicitudes — /api/solicitudes

MétodoRutaBodyDescripción

Categorías disponibles

Plomería · Electricidad · Pintura · Carpintería · Limpieza · Jardinería · Otro

ℹ️
El filtro por categoría se recomienda aplicarlo en el frontend sobre la respuesta del GET /: data.filter(s => s.categoria === cat). Esto evita índices compuestos adicionales en Firestore.
Ofertas

Ofertas — /api/ofertas

MétodoRutaBodyDescripción
POST / { solicitudId, empleadoId, precioOfertado } Crea oferta. Un empleado solo puede tener una oferta por solicitud (409 si ya existe). Notifica al empleador vía socket.
GET /:solicitudId — Lista todas las ofertas de una solicitud. Incluye empleadoNombre y calificacionPromedio.
PUT /:id/aceptar — Acepta oferta: crea proyecto automáticamente, rechaza demás ofertas, cambia solicitud a en_proceso. Notifica al empleado.

Respuesta de aceptar oferta

{ "success": true, "mensaje": "Oferta aceptada. Proyecto creado.", "data": { "proyectoId": "ABCD1234", "titulo": "Reparación eléctrica", "empleadorId": "...", "empleadoId": "...", "monto": 120.00, "estado": "activo" } }
Proyectos

Proyectos — /api/proyectos

MétodoRutaBodyDescripción
GET /usuario/:uid — Proyectos donde el usuario es empleador o empleado. Ordenados por fecha desc.
GET /:id — Detalle de un proyecto.
PUT /:id/pagar — Simula pago: descuenta monto del saldo del empleador y pasa a en_escrow. Error 400 si saldo insuficiente. Notifica al empleado.
PUT /:id/finalizar — El empleado marca el trabajo como terminado. Genera código de 6 dígitos y pasa a pendiente_codigo.
POST /:id/codigo { codigo } El empleador ingresa el código. Libera el pago (90% del monto al empleado en gananciasTotales). Pasa a completado.
PUT /:id/cancelar — Cancela proyecto en estado activo o en_escrow. Si estaba en escrow, devuelve el saldo al empleador. Reactiva la solicitud original. Notifica a ambos.
POST /:id/fotos multipart/form-data campo fotos[] Sube hasta 10 fotos finales del trabajo. Las URLs se agregan al array fotosFinales.

Calificaciones

Calificaciones — /api/calificaciones

MétodoRutaBodyDescripción
POST / { proyectoId, estrellas, comentario? } El empleador califica al empleado. Solo proyectos completado. Una sola vez por proyecto (409 si ya existe). Recalcula el promedio del empleado.
POST /empleador { proyectoId, estrellas, comentario? } El empleado califica al empleador. Mismas restricciones. Recalcula el promedio del empleador.
GET /empleado/:uid — Historial de calificaciones recibidas por el empleado. Incluye empleadorNombre, estrellas y comentario.
GET /empleador/:uid — Historial de calificaciones recibidas por el empleador. Incluye empleadoNombre, estrellas y comentario.

El campo estrellas debe ser un entero entre 1 y 5. El promedio se actualiza automáticamente en el documento del usuario.

Chats

Chats — /api/chats

MétodoRutaBodyDescripción
POST /:proyectoId/mensajes { autorId, texto } Envía mensaje. Valida que autorId sea participante del proyecto. Emite new_message al room del proyecto y nueva_notificacion al otro participante.
GET /:proyectoId/mensajes — Historial de mensajes ordenado por timestamp ascendente.
⚠️
No insertar el mensaje en el DOM inmediatamente al enviarlo. El servidor emite new_message al room del proyecto para todos los participantes, incluyendo quien lo envió. Renderizar solo al recibir el evento socket para evitar duplicación.

Estructura de un mensaje

{ "id": "doc-id-firestore", "autorId": "uid-del-autor", "texto": "Hola, ¿cómo va el trabajo?", "proyectoId": "ABCD1234", "autorNombre": "Carlos Ruiz", "proyectoTitulo": "Reparación eléctrica", "timestamp": { "_seconds": ... } }

Socket.io

Eventos en tiempo real

Conectar a http://<host>:5000 usando el cliente de Socket.io.

Eventos que el cliente emite al servidor

EventoPayloadDescripción
join_user { uid } Obligatorio al iniciar sesión. Une al socket a la sala personal del usuario (identificada por su UID). Sin esto no llegarán las notificaciones personales.
join_room { proyectoId } Unirse al chat de un proyecto para recibir new_message, typing y stop_typing.
typing { proyectoId, nombre } Notificar que el usuario está escribiendo en ese chat.
stop_typing { proyectoId } Notificar que dejó de escribir.

Eventos que el servidor emite al cliente

EventoSalaPayloadDescripción
nueva_notificacion uid personal { id, uid, tipo, texto, datos, leida, fecha } Notificación nueva en tiempo real. Misma estructura que el REST. Fecha como ISO string.
nueva_solicitud broadcast { id, titulo, categoria } Nueva solicitud publicada. Solo relevante para empleados.
new_message proyectoId { id, autorId, texto, proyectoId, autorNombre, proyectoTitulo } Mensaje de chat. Llega a todos en el room, incluyendo el emisor. No pre-renderizar.
typing proyectoId { nombre } Otro participante está escribiendo.
stop_typing proyectoId — El otro participante dejó de escribir.
